# Розділ 12. Обрати методологію розробки

Для розробки інформаційної системи табельного обліку обрано методологію **Agile (Scrum)**. Такий вибір зумовлений високим ступенем зв'язності компонентів системи та необхідністю постійного тестування інтерфейсів різними категоріями користувачів (працівники, HR, адміністратори).

### 1. Обґрунтування вибору
* **Гнучкість:** Можливість швидко адаптувати систему до вимог різних моделей турнікетів та СКУД.
* **Ітеративність:** Процес розділено на спринти (2 тижні), що дозволяє демонструвати робочі модулі (наприклад, сервіс авторизації або мобільний чек-ін) на ранніх етапах.
* **Зворотний зв'язок:** Регулярні зустрічі з HR-відділом як головним замовником для уточнення логіки нарахування годин.

### 2. Організація розробки
* **Product Backlog:** Містить усі User Stories (відмітка приходу, формування звітів, керування акаунтами).
* **Sprint Planning:** На початку кожного циклу команда обирає завдання, що мають найвищий пріоритет для стабільності системи.
* **Daily Scrum:** Щоденна синхронізація розробників сервісів Attendance та Leave для забезпечення цілісності даних.
* **Definition of Done (DoD):** Завдання вважається виконаним лише після проходження Unit-тестів, код-рев’ю та успішної інтеграції з базою даних PostgreSQL.
