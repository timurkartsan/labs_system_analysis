# Розділ 8. Обґрунтування вибору типу бази даних

Для реалізації інформаційної системи табельного обліку та контролю робочого часу обрано **реляційну систему управління базами даних (RDBMS)**, а саме **PostgreSQL**. Даний вибір базується на аналізі структури даних та вимог до надійності системи.

### 1. Відповідність моделі даних

Дані системи є суворо структурованими та мають складні зв'язки (1:1, 1:N, M:N) між сутностями `Employee`, `Department`, `AttendanceRecord` та `LeaveRequest`. Реляційна модель дозволяє ефективно реалізувати ці зв'язки через механізми зовнішніх ключів (Foreign Keys).

### 2. Забезпечення цілісності (ACID)

Оскільки система оперує даними, що безпосередньо впливають на нарахування заробітної плати (Payroll), критично важливо забезпечити принципи ACID:

- **Атомарність:** Списання днів відпустки та створення запису `LeaveRequest` мають відбуватися як одна неподільна операція.
- **Узгодженість:** Механізми Constraints (Unique, Not Null) гарантують, що в системі не з'являться записи без прив'язки до працівника або заблокованого акаунта.

### 3. Гнучкість та аналітичні можливості

- **SQL запити:** Використання складних JOIN-операцій є оптимальним для генерації щомісячних звітів по відділах.
- **Підтримка JSONB:** Використання типу JSONB у PostgreSQL дозволяє зберігати неструктуровані метадані від пристроїв (IoT-турнікетів, інформація про мобільні пристрої `device_info`) без втрати продуктивності.

### 4. Порівняння з альтернативами

Використання NoSQL (наприклад, MongoDB) було відхилено, оскільки відсутність жорстких схем та механізмів транзакцій між різними колекціями підвищує ризик десинхронізації даних про відпрацьований час та відпустки.
