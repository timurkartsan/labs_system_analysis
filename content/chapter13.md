# Розділ 13. Документувати результати проєкту

Документація системи є комплексним набором артефактів, необхідних для підтримки, експлуатації та подальшої інтеграції системи з іншими бізнес-процесами компанії.

### 1. Склад проєктної документації

- **Технічне завдання (ТЗ):** Опис функціональних вимог, ролей користувачів та бізнес-правил (наприклад, обмеження на одну відкриту зміну).
- **Опис архітектури (ADR):** Документування вибору трирівневої архітектури, використання REST API та вибору PostgreSQL як основного сховища даних.
- **API Reference (OpenAPI 3.1):** Специфікація всіх ендпоінтів для зовнішніх інтеграцій та мобільного додатка, включаючи опис заголовків ідемпотентності (`Idempotency-Key`).
- **Database Schema:** ER-діаграма та опис типів даних (UUID, JSONB, timestamptz) і створених індексів.

### 2. Користувацькі посібники

- **Інструкція працівника:** Опис роботи з мобільним клієнтом, процедура чек-іну та подачі заявки на відпустку.
- **Мануал адміністратора:** Налаштування ролей (RBAC), керування доступами та моніторинг помилок інтеграції з турнікетами.
- **Довідник звітів:** Опис структури та логіки формування звітів для Payroll-систем.

### 3. Регламент підтримки

- **Operational Manual:** Інструкції з розгортання через Docker, налаштування реплікації бази даних та Redis для кешування сесій.
- **Security Policy:** Опис методів автентифікації (JWT/OAuth 2.1) та журналювання дій користувачів для аудиту.
